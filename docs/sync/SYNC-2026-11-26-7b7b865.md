## Then: Wayland presenting

Presenting on Wayland works. The protocol error came from QtTest: with `QT_QTESTLIB_RUNNING` set, Qt's Wayland
windows attach a placeholder shared-memory buffer on expose (qtbase 6.10.2, `QWaylandWindow::sendExposeEvent`),
which a Vulkan surface with explicit sync rejects. The app never sets it; `tst_present` now unsets it. Also fixed: the
swapchain is released on `SurfaceAboutToBeDestroyed` (the window container destroys the platform window before the
window's destructor runs), and presenting prefers mailbox (FIFO can block while a Wayland window is hidden).

DMA-BUF import is not done. Mapping a Vulkan-decoded frame to DRM PRIME crashes in ANV, and VA-API (the path that
exports DMA-BUFs) has no driver on this machine.

## Then: DMA-BUF import

With intel-media-va-driver installed, VA-API decodes first. Its frames go on as DMA-BUFs (`VideoFrame::dmabuf`,
made in `Decoder.cpp`). `GpuVulkan.cpp` imports each layer with its DRM modifier and copies it into the pixel buffer
on the GPU. CPU users get the frame downloaded once (`VideoFrame::bytes()`). Tests: `tst_dmabuf` (H.264 and 4K 10-bit
HEVC against the CPU's composite, the import counted, and the decoder's budget). VA-API export (`h264_vaapi`) passes
the colour check, so export is hardware-encoded again.
